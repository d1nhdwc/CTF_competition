## PE properties

`RV64VMv4.exe`:

- PE32+ x86-64 console executable.
- Preferred image base: `0x140000000`.
- Entry RVA: `0x1be0`.
- SizeOfImage: `0x4000`.
- Sections: `.text` RX at RVA `0x1000`, `.rdata` R at RVA `0x2000`, `.pdata` R at RVA `0x3000`.
- DllCharacteristics: `0x8160` = high entropy VA, dynamic base, NX compat, terminal server aware.
- No load config directory, so no CFG metadata in the main executable.
- Linker version: MSVC `14.50`.

Imports:

- `KERNEL32.dll`: `ReadFile` IAT RVA `0x2000`, `GetCommandLineW` `0x2008`, `GetStdHandle` `0x2010`, `WriteFile` `0x2018`, `CreateFileW` `0x2020`, `CloseHandle` `0x2028`, `HeapAlloc` `0x2030`, `GetFileSize` `0x2038`, `GetProcessHeap` `0x2040`.
- `SHELL32.dll`: `CommandLineToArgvW` IAT RVA `0x2050`.

## Main and context layout

`main` is at `base+0x1be0`.

Flow:

- Parses command line through `GetCommandLineW` and `CommandLineToArgvW`.
- Allocates zeroed heap context with `HeapAlloc(GetProcessHeap(), 9, 0x20110)`.
- Opens payload path with `CreateFileW`.
- Rejects payloads larger than `0x10000`.
- Reads payload into `ctx+0x110`.
- Sets `ctx->pc = ctx+0x110`.
- Sets guest `sp` at `ctx+0x20` to `(ctx+0x2010f)&~0xf`.
- Calls `execute(ctx)` at `base+0x1000`.
- Return address after the call is `base+0x1ccc`.

Context:

- `ctx+0x00`: guest `pc`, represented as a host virtual pointer.
- `ctx+0x10 + 8*n`: guest register `x[n]`.
- `ctx+0x18`: guest `ra`.
- `ctx+0x20`: guest `sp`.
- `ctx+0x60`: guest `a0`.
- `ctx+0x98`: guest `a7`.
- `ctx+0x110`: guest code/data buffer.

## Interpreter

`execute` is at `base+0x1000`.

Confirmed behavior:

- It zeroes guest `x0` each dispatch iteration.
- Fetches a 32-bit instruction from host pointer `[ctx->pc]`.
- Decodes RV64I/RV64M instructions by opcode/funct fields.
- Implements `LB/LBU/LH/LHU/LW/LWU/LD` as direct host memory reads.
- Implements `SB/SH/SW/SD` as direct host memory writes.
- Implements arithmetic, shifts, branches, `JAL`, `JALR`, multiply/divide.
- `JALR` masks the low bit.
- No bounds check exists for guest PC, load addresses, or store addresses.

Syscalls:

- `a7=0x5d`: return `0` from `execute`.
- `a7=100`: `print_char_string`; treats guest `a0` as a host pointer, computes length with an unbounded byte scan, then writes via `WriteFile(GetStdHandle(-11), ptr, len, ...)`.
- `a7=101`: print `a0` as hex.
- `a7=102`: print `a0` decimal.
- `a7=103`: print newline.
- Unknown syscall returns `2`.
- Invalid instruction returns `1`.

The previously observed local exit code `5` is Windows access violation `0xc0000005` as surfaced through WSL, not a documented VM status.

## Proven primitives

Probe payloads generated by `build_payload.py` demonstrated:

- `leak_pc.bin`: `auipc` leaks the host pointer of guest code.
- `read_ctx.bin`: guest can read the VM context by subtracting `0x110` from the guest code pointer.
- `heap_rw.bin`: guest can write and read host heap memory.
- `read_image_base.bin` and `read_80000000.bin`: unmapped host addresses crash with access violation.
- `find_base.bin`: main PE base can be derived under ASLR by scanning loader metadata near the heap allocation and validating `MZ`/`PE` plus executable-specific import strings.
- `test_iat_write.bin`: writing the main IAT crashes because `.rdata` is read-only.
- `scan_return_addrs.bin`: host stack pointers can be found through heap metadata; stack return slots containing `base+0x1ccc` are visible.
- `debug_final_state.bin`: final resolver finds the current return slot, `kernel32`, `ntdll`, `RtlExitUserProcess`, and a `pop rcx; ret` gadget.

## Final exploit strategy

The final payload avoids fixed ASLR addresses.

Stages:

1. Recover `ctx` using `auipc - 0x110`.
2. Find main module base by scanning nearby heap/loader metadata and validating PE headers.
3. Find the current `execute()` return slot on the host stack. The final scanner requires:
   - slot value is `main_base+0x1ccc`;
   - saved `rbx` at `slot-8` equals `ctx`;
   - saved `rsi` at `slot-24` equals `ctx+0x110`.
4. Resolve `kernel32` from main IAT `CreateFileW`.
5. Parse `kernel32` imports to find an `ntdll` function pointer and the resolved `RtlExitUserProcess` IAT entry.
6. Scan `ntdll` `.text` for `pop rcx; ret`.
7. Write `L"C:\\chall\\flag.txt"` and two fake VM contexts inside the existing zeroed heap allocation.
8. Overwrite the current native `execute()` frame:
   - saved `rdi = fake_file_context`;
   - saved `rbx = fake_file_context`;
   - return address = `main_base+0x1c37`.
9. `main+0x1c37` reuses the binary's own file loader to call `CreateFileW`, `GetFileSize`, `ReadFile`, and `CloseHandle`. It reads the flag into `fake_file_context+0x110`.
10. A small ROP chain returns into `execute(print_context)`. That context executes:
    - `a7=100; ecall` to print `a0=flag_buffer`;
    - `a7=0x5d; ecall` to return.
11. Tail chain calls `RtlExitUserProcess(0)` with correct stack alignment.
